# 可插拔资产实施计划

目标：自定义地图通过布局配置组合资产；同契约模型可只替换资源链接。后续从首个未完成阶段继续，验收后再勾选。本计划聚焦建模与组合边界，游戏规则仍归 `game-core`。

## 三层职责

- **地图布局**：定义存在的六边形位置、相邻关系、共享边与共享顶点；整张地图不固化为一个 GLB。
- **资产组合**：按位置装配地块、数字、建筑与装饰；数字值和地块类型分别配置，附着物允许缺省。
- **视觉主题**：把语义资产标识映射为模型链接与材质样式；换皮不改变布局、数字值、归属和玩法含义。

## 模块边界

| 模块 | 责任与约束 |
| --- | --- |
| 场景环境 | 桌面、海面、灯光；独立于地图布局 |
| 地图结构 | 支持自定义六边形排列；相邻地块引用同一条边、同一个顶点 |
| 地块 | 统一占地、地表基准和接缝；独立替换地形外观 |
| 地块附着物 | 地块上的可选挂载对象，是数字与装饰等对象的组合分类 |
| 数字标记 | 属于附着物；底座模型与数字内容独立，可移除，不为每个数字重复制作底座 |
| 边对象 | 道路、港口、边界段共享定位方式，但分别约定占地与朝向，不能任意互换 |
| 顶点建筑 | 村庄、城市共享落脚点；升级替换模型，玩家颜色使用约定材质槽 |
| 活动物体 | 强盗等独立资产，通过地块挂点定位，可在地块之间移动 |
| 装饰 | 需要独立复用或变化才拆分；固定细节留在父资产中 |
| 交互表现 | 高亮、选中和建造提示独立于地块模型，可由渲染端生成 |

## 资产契约

- 第一阶段确定统一单位、六边形半径及尖顶/平顶朝向、地表高度、原点和正面；数值记录在本节后再批量建模。Blender 使用 Z-up，导出 GLB 使用 Y-up，运行时不得重复旋转补偿。
- 地块原点位于中心地表基准；道路以边中点、建筑以落脚点为定位基准。同类资产必须遵守相同尺寸和占用范围，不能靠逐模型手调偏移实现替换。
- 地块保留 `anchor_number`、`anchor_robber`，可选装饰挂点为 `anchor_decor_*`；在同类资产内固定名称、局部位置与净空。数字和强盗占用不同位置，装饰不侵入数字、道路和建筑空间。
- 挂点随 GLB 保留，不能只存在于被排除的 Blender 集合中。数字可缺省，支持数字的地块应保留数字挂点；不兼容资产明确报告，不静默错位加载。
- 相邻地块接缝对齐；高度起伏留在内部或使用约定过渡。独立边界段和转角适配不规则地图；港口朝向外海，只占用配置允许的海岸边。
- 语义类型、数字值、玩家归属和规则独立于 GLB 文件名及节点名称；节点名称仅用于挂点和材质接口。换色不得污染其他玩家共享的材质。
- 普通资产不包含展示相机和灯光；材质须可导出或烘焙为 GLB 可用形式。重复模型复用几何体和材质，保留实例化条件。
- 面数、材质数和贴图预算由组合样板在目标观看距离下验证后记录，不以堆叠细节替代审美质量。

### 森林样板契约 v1（2026-10-10）

- 单位为 Blender unit（导出比例 1），平顶六边形外接半径 `3`、对边距 `3√3`，顶点位于 XY 平面角度 `0° + 60°n`。中心地表为 `(0,0,0)`，底面 `z=-0.30`，正面为 `-Y`；边界顶面严格为 `z=0`。GLB 转换为 Y-up：`(x,y,z) → (x,z,-y)`。
- `anchor_number=(-0.55,-0.72,0)`，圆柱净空半径 `0.50`、高度 `0.40`；`anchor_robber=(0.70,-0.83,0)`，净空半径 `0.34`、高度 `1.15`。净空内不放树木和独立装饰，支持二者同时挂载。v03 起挂点落在真实地面，修正早期草稿 `z=0.025` 的悬空偏移。
- 外沿向内 `0.28` 为道路/建筑接缝预留带，不放树冠、树干或凸起装饰；内部可起伏，挂点周围保持平坦。这是新资产基准，不代表已有游戏坐标已适配。
- 早期组合样板使用数字与强盗占位体；强盗与空白数字底座现已独立交付，数字内容仅为临时排版预览，运行时尚未实现。二者均不能固化到森林 GLB。阶段完整验收前，下列勾选保持未完成。

### 强盗契约 v1（2026-10-16）

- 根节点 `robber`，底面中心为原点，导出比例 1；Blender Z-up、正面 `-Y`，GLB Y-up、正面 `+Z`。按地块 `anchor_robber` 变换挂载，不做逐地块缩放或偏移。
- 全模型含底座须位于半径 `0.34`、高 `1.15` 的净空内；当前实际半径 `0.3132`、高 `1.10983`。静态棋子，不包含骨骼、动画或玩家换色槽。
- 源文件的 `REVIEW_ONLY` 棚光与相机不进入 GLB。当前 93,650 三角面、15 材质、约 2.32 MB，仅为单棋子记录，尚非桌面端性能预算验收。

### 数字底座契约 v1（2026-10-16）

- `number-token` 是通用空白底座，不按数字复制 GLB；深胡桃木薄边、暖象牙色牌面、克制的金棕描边。底面中心为原点，比例 1，半径 `0.478`、高 `0.101`，直接挂到地块 `anchor_number`。
- 数字挂点 `anchor_content=(0,0.055,0.1015)`，内容居中，最大宽高 `0.60×0.42`；可选概率点挂点 `anchor_probability=(0,-0.245,0.1015)`，最大宽高 `0.34×0.045`。均为 Blender 局部坐标，内容法线 `+Z`、字顶朝 `+Y`；GLB 对应法线 `+Y`、字顶朝 `-Z`，坐标遵循统一转换，不重复旋转。
- 牌面顶高 `0.100`，内容挂点预留 `0.0015` 防闪烁；数字、点数及强调色由配置/渲染层生成，不固化为底座材质或几何体。移除数字不移除底座；整牌移除由组合层控制。
- 排版预览覆盖 `1–12`；标准卡坦地块数字为 `2–12` 且不含 `7`，`6/8` 用红色强调，沙漠默认无数字（[官方规则](https://www.catan.com/sites/default/files/2021-06/catan_base_rules_2020_200707.pdf)）。合法数字和概率规则归玩法配置，资产不限定玩法。
- 本轮只交付底座模型与内容接口，未实现 Electron 动态文字；本机字体仅用于临时评审，不分发字体文件。当前 `3,828` 三角面、`3` 材质，重复底座可共享几何体与材质。

### 顶点建筑契约 v1（2026-10-17）

- `settlement`（木梁灰泥民居）与 `city`（石砌门楼＋侧厅）均以底面中心 `(0,0,0)` 为原点，比例 1、Blender 正面 `-Y`；GLB Y-up、正面 `+Z`。按布局中的**唯一共享顶点**挂载，升级只替换资源链接，不改变顶点变换。
- 全模型含屋檐、台阶和旗帜占地半径不超过 `0.28`、高度不超过 `0.80`，兼容地块边沿预留带；村庄实际半径约 `0.2414`、高 `0.535`，城市约 `0.2564`、高 `0.724`。不额外叠加通用基座。后续道路须在顶点中心半径 `0.28` 之外收口，避免穿过建筑。
- 每类只交付一份模型，不为玩家颜色复制文件。GLB 分为 `<asset-id>.body` 与 `<asset-id>.player`；`player_color` 材质只覆盖屋顶和城市旗帜，石材、木梁、灰泥不变。材质名是视觉接口，不承载玩家归属规则。
- 换色输入是一项玩家颜色；运行时转换到线性 RGB 后修改 `player_color` 的 base color，保留粗糙度与几何明暗。普通对象按玩家复制/缓存该材质，禁止修改所有玩家共享的原材质；几何可共享。大量重复建筑可对玩家色网格按颜色分组实例化，或用中性基色配实例颜色，避免重复乘上默认蓝色。
- 红、蓝、象牙白、橙仅为评审示例；任意颜色可配置，但相近颜色的辨识需另验。当前交付模型和材质接口，**未实现 Electron 换色代码**；三地块共享顶点组合不代表不规则整盘、道路衔接或性能全部验收。

### 道路契约 v1（2026-10-17）

- `road` 是共享边上的独立石铺道路棋子，原点在边中点的地面，长轴为局部 `X`；Blender Z-up，GLB Y-up，统一轴转换后不额外补旋转。同一条共享边只放一份道路。
- 适配边长 `3`：可见长度 `2.40`、宽 `0.36`、高 `0.074`，底面为 `0`；两端距逻辑顶点各 `0.30`，避让建筑半径 `0.28`。无建筑时顶点处保留地面间隙，不拉长道路填满，也不视为连续路面接缝。独立路口补片尚未制作。
- 逻辑端点挂点 `anchor_edge_a=(-1.5,0,0)`、`anchor_edge_b=(1.5,0,0)` 随 GLB 保留，不等于可见网格的端面。运行时以顶点中点定位，并让长轴对齐端点连线；模型无通行方向语义，规则归组合层。
- `road.body` 保留暖石材与细木边，`road.player` 的唯一 `player_color` 材质控制两侧路缘；换色与建筑相同，按玩家隔离材质、共享几何，不按颜色重复导出模型。
- 已完成独立资产 Computer Use 基线评审和 GLB 回导并归档，路径与验收边界见资产清单。共享顶点样板通过占地／原位升级检查；低角度前景遮挡仍是组合限制，不能据此勾选整阶段或宣称全地图可读性通过。Electron 换色与实例化未实现。

### 港口契约 v1（2026-10-18）

- `harbor` 为双栈桥＋小帆船，不包含海面、地块或交易牌。原点是海岸边中点的地表，长轴 `X`、外海方向 **`+Y`**；GLB 对应外海 `-Z`。按海岸法向确定方向，不能仅凭无序端点连线旋转。逻辑端点 `anchor_edge_a/b=(±1.5,0,0)`，边长 `3`。
- Blender 包围盒 `X=[-1.24,1.24]、Y=[0,1.975]、Z=[-0.33,1.15]`；海面基准 `z=-0.22`（GLB `y=-0.22`），桩脚允许入水。两端建筑半径 `0.28` 保持净空。登岸板从 `y=0` 接地，沿岸道路范围 `|y|≤0.18` 内顶面不高于 `z=0`，道路可独立放置/移除。
- `anchor_trade=(-0.79,1.64,0.095)`（GLB `(-0.79,0.095,-1.64)`）。六种 `harbor-marker-{generic,lumber,brick,ore,grain,wool}` 共用底面中心原点、`0.72×0.62` 占地，直接按挂点变换替换；空缺则仅保留木托板。文字法线 `+Z`、字顶 `+Y`；这是固定世界朝向，可独立绕法线转 `180°`，不是自动朝镜头文字。
- 通用牌显示 `? / 3:1`，资源牌显示资源浮雕／`2:1`；文字已转网格，无外部字体依赖。此批是静态可替换牌，不是动态文字实现；自定义比例需另一兼容牌或后续内容渲染。玩法读取配置，不从文字/文件名反推规则。港口是共享设施，不设 `player_color`。
- 六个边方向的端点/外海朝向校验及单海岸组合已检查；**内凹海湾、相邻港口、边框和整盘未验收**。布局层须为完整港口占地检查外海净空，不得仅因某边是海岸就无条件挂载。海面/边框仍独立，后续边框必须避让登岸板，不能覆盖后导致悬空。

### 地图基座契约 v1（2026-10-18）

- 基座是组件集合，不是固定 19 孔整盘：`map-support-hex`、`coast-edge`、`coast-edge-harbor`、`coast-corner-convex/concave`、`sea-surface`。地块、港口、数字仍独立；不导出合并整盘 GLB。
- 承托与地块共用地表原点、半径 `3`；承托顶面 `z=-0.30`、底面 `-0.54`，`anchor_tile=(0,0,0)`。地块原有底座保留，不另加地表层、不抬高地块。承托通常被地块/海面遮住，可按主题省略。
- 岸段原点为边中点；`X` 沿边、`+Y` 向海，逻辑端点 `X=±1.5`，可见段 `X=±1.22`。两端各留 `0.28` 给转角；`anchor_join_a/b=(±1.22,0,0)`。岸段与转角的端截面必须完全一致，不能各自独立倒角。
- 岸沿向海宽 `0.46`、底高 `-0.54`，顶部 `0≤y≤0.28` 为 `z=0` 水平承托面，之后折面入水；不进入地块内部。道路外半幅与半径 `0.28` 的顶点建筑有落脚面。
- 有港口的边使用 **`coast-edge-harbor` 替换普通岸段**，不是叠放。两处登岸槽 `|x|∈[0.869,1.211]、0≤y≤0.28` 下沉到 `z=-0.04`，避让现有木登岸板；`anchor_harbor=(0,0,0)`。港口移除时恢复普通岸段，转角无需变更。
- 转角原点为逻辑顶点，局部 `+X` 为进入该顶点的边方向；沿边定向使陆地在右、海在左。外凸角转 `-60°`（陆地内角 `120°`），内凹角转 `+60°`（内角 `240°`）。接口 `anchor_join_in=(-0.28,0,0)`、`anchor_join_out=(0.14,∓0.242487,0)`；内湖边界方向与外轮廓相反，不能统一强制顺时针。
- 海面为中心原点的 `2×2` 平面、法线 `+Z`，放到 `z=-0.22`，按地图范围缩放 XY；GLB 对应 XZ 平面、`y=-0.22`，统一轴转换不变。当前哑光蓝绿静态材质，无波浪动画、透明折射或自动岸线泡沫；也可由渲染平面替代。
- 布局使用平顶轴坐标：`x=4.5q、y=3√3(r+q/2)`。边/顶点以整数格点去重，不能用不同地块浮点世界坐标直接当标识。每地块一个承托，仅海岸边放岸段，仅海岸顶点放凹/凸角；三地块共享顶点不放角。模型链接由主题映射，重复组件共享几何。
- 港口完整占地仍须同时避让地形与其他港口；六地块样板中单港都可避开地形，但有 **7 对候选港口包围矩形相交**，不能全部挂上。使用保守占地可拒绝潜在碰撞，不等于精确网格碰撞或玩法合法性判断。
- 已完成六地块不规则样板的 Computer Use 检查、GLB 回导和实际端截面对齐；单/双地块、环形留洞、分离岛屿、19 地块仅追加拓扑检查。**Electron 配置加载、全排列视觉、相邻港口实景、性能与打包未验收**；基座几何不是运行时自动组装器。复现入口与路径见资产清单。

## 按顺序实施

- [ ] **1. 尺寸、插槽与审美基准**：产出契约数值、挂点位置/净空、标准地块和固定评审视角；验收轴向、拼接、落脚点与中世纪风格基准，再推进批量资产。
- [ ] **2. 单地块组合样板**：产出森林地块、可拆数字牌与强盗占位体；验收数字独立替换/移除、数字与强盗共存、树木不遮挡标记，并记录初始资源预算。
- [ ] **3. 自定义地图拼接**：产出不同数量与排列的地图样板；验收共享边/顶点唯一、无接缝裂隙，不规则边界及内凹海岸方向正确。
- [ ] **4. 地形与装饰系列**：产出地形系列及可复用树木/岩石；验收统一尺度、材质语言与细节密度，整盘可辨识，重复资产可实例化。
- [ ] **5. 边对象与建筑**：产出道路、村庄、城市、港口和边界段；验收边长/朝向适配、村庄原位升级、玩家换色独立及海岸港口组合。
- [ ] **6. 活动物体、主题与交互**：产出强盗成品、替代森林模型和主题映射样例、独立交互提示；验收强盗移动、只换模型链接即可换皮，布局与规则含义不变。

## 验收与执行入口

每阶段记录产物路径、验证证据及遗留问题；缺少证据的项目保持未完成。关键回归场景：森林换皮、移除数字、数字与强盗共存，以及不规则地图的边/顶点/港口组合。

建模使用 [catan-blender-modeling Skill](../.agents/skills/catan-blender-modeling/SKILL.md)，审美以其 [风格规范](../.agents/skills/catan-blender-modeling/references/art-direction.md) 为准；导出与提交遵循 [资产工作流](blender-asset-workflow.md)。

阶段验收不因资产数量增加而自动完成。资产路径与建模验收统一维护在 [模型资产清单](asset-inventory.md)。已实现 [Electron 19 地块＋9 港口展示样板](desktop-map-preview.md)：配置组装、刷新地形/数字、动态文字、玩家换色与实例化；已检查 macOS 开发和构建后本地加载。下一步是正式镜头/遮挡策略与游戏状态接入，再按需做主题变体；不将此样板视为全部阶段或 Windows/安装包验收完成。

## 已确认的造型约束

- 延续明亮、哑光、手绘游戏感；地貌连续接地，不用独立球体堆山。主形体靠近边缘，但保留拼接带。
- 砖使用氧化铁红山体、红土地面与侧边砖窑；不要恢复工坊桌子、桶等填空道具。石使用宽阔蓝灰采石崖、暖木吊机与小型交易棚，不只是砖地块换色。
- 麦使用柔和旧木/灰橄榄屋顶、灰泥与亚麻帆；麦田有疏密和起伏，不用棋盘格屋顶或僵硬阵列。羊以浅绿牧场、羊群和低矮茅草羊舍为主，不用密林填空。
- 沙漠是留白例外：空旷暖沙地与连续低缓沙丘，不要求丰富道具或满铺细节。
- 强盗采用黑衣中世纪领主方向：炭黑长披风、深灰遮面布、黑褐皮革与少量黑铁；以肩部剪影、兜帽阴影和稳重站姿形成气场，不用花哨配色、科幻头盔、发光部件。仅强盗采用此深色方案，其他地块保留既有明亮画风。
- 装饰服务资源叙事，数字与强盗可独立移除；换造型不改组合契约。挂点验证以资产清单最新复核结论为准。
