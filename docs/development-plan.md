# 开发计划

项目按可独立验收的阶段推进。当前只推进建模和桌面端 3D 原型，服务端相关阶段暂缓。

建模与组合模块按 [可插拔资产实施计划](modular-asset-plan.md) 逐阶段验收；制作与视觉评审使用 [Blender 建模 Skill](../.agents/skills/catan-blender-modeling/SKILL.md)。

当前模型路径、挂点复核结果及下一批建模顺序见 [模型资产清单](asset-inventory.md)。

## 1. 建模与资产管线

- 确定整体画风、世界单位、坐标方向、原点、轴心和命名规范。
- 建模地形板块、海洋、港口、道路、村庄、城市、强盗和基础装饰物。
- 建立共享材质与纹理规范，控制贴图尺寸和材质数量。
- 统一从 Blender 导出 GLB，并验证模型、材质、法线、动画和尺寸。
- 产出代表性资产集，确保桌面端能够正确加载和显示。

## 2. 桌面端 3D 原型

- 搭建基础场景、相机、灯光、阴影和环境效果。
- 实现六边形地图布局及 GLB 资产加载。
- 实现鼠标悬停、选中、镜头移动和基础反馈。
- 对重复地形、道路和建筑使用实例化，并建立基础性能指标。
- 完成不依赖服务端的本地棋盘演示。

## 3. 前端交互与本地流程

- 建立首页、设置、房间和对局界面的基础结构。
- 定义场景状态与界面状态的边界。
- 实现本地回合演示、建造预览和资源面板。
- 完成分辨率、窗口缩放和 Windows/macOS 基础适配。

## 4. 游戏核心与共享协议

- 在 `game-core` 中定义确定性状态转换和 `RuleConfig`。
- 在 `protocol` 中定义 `GameCommand`、`GameState`、事件及 Zod schema。
- 覆盖标准规则、非法操作和确定性结果。
- 保持游戏规则与渲染、网络和数据库解耦。

## 5. 登录与数据持久化

- 确认游客模式和账户体系的产品范围。
- 设计用户、会话、房间快照和有序事件的数据结构。
- 接入 PostgreSQL、Drizzle 迁移和认证接口。
- 完成桌面端登录态保存、退出和过期处理。

## 6. 房间与匹配

- 实现建房、加入、邀请、准备和离开流程。
- 使用 Colyseus 管理房间连接、实时状态和计时器。
- 实现公开房间或匹配队列，并处理满员、超时和重复加入。
- 完成断线重连和房间生命周期处理。

## 7. 联机对局

- 接入服务端权威的命令校验和状态广播。
- 在单个 PostgreSQL 事务中写入有序事件与房间快照。
- 完成回合计时、掉线恢复、结束结算和异常处理。
- 验证 3–4 人完整对局流程。

## 8. 完善与发布

- 补充音效、动画、设置、引导和可访问性。
- 优化模型、纹理、加载时间、内存和渲染性能。
- 完善自动化测试、崩溃日志和版本迁移。
- 配置 Windows/macOS 安装包、签名和发布流程。

## 模块边界

- `apps/desktop`：Electron 生命周期、React UI、Three.js 场景和资产加载。
- `apps/server`：登录、房间、匹配、Colyseus 和数据库访问；当前暂停开发。
- `packages/game-core`：不依赖 UI 和网络的确定性游戏规则。
- `packages/protocol`：桌面端与服务端共享的数据结构和边界校验。
- `docs`：资产规范、玩法说明、架构决策和开发计划。
