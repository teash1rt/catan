# 最小游戏状态与初始放置

本方案已按确认后的实施计划落地到共享协议与游戏核心；界面、服务端和数据库不在本轮范围内。

## 边界与接口

- `protocol` 定义状态、命令、事件、执行结果与 Zod schema；数据均可 JSON 序列化。
- `game-core` 提供 `createGame({ map, players, rules })`、`applyGameCommand(state, actorId, command)` 和 `getLegalPlacements(state)`。
- 调用方传入有序的 3–4 名玩家，第一位先行动。操作者身份独立于命令，由调用方提供可信身份，不能通过命令指定建筑归属。
- 本轮 `RuleConfig` 只支持 `{ preset: "classic" }`。规则参数集中维护，不增加玩法变体。
- 转换不使用时间或随机数，不原地修改输入；成功返回新状态和本次有序事件，失败仅返回错误码。

`createGame` 接受 `{ id: string }` 玩家列表。状态中的玩家额外包含五类资源计数，当前行动者由 `state.phase.playerId` 指定；两类放置阶段还包含 `round`，道路阶段额外包含本次村庄的 `vertexId`。建筑分别存为 `{ vertexId, playerId }` 与 `{ edgeId, playerId }` 数组。

`getLegalPlacements` 返回 `{ settlementVertexIds, roadEdgeIds }`，非当前阶段的列表为空；待掷骰时两者都为空。初始化或位置查询遇到无效状态会抛出校验错误，命令执行则通过 `{ ok: false, error }` 返回错误码，包括无效状态的 `INVALID_STATE`，不返回事件或新状态。成功结果为 `{ ok: true, state, events }`。

## 标准初始放置

- 四人顺序为 `A → B → C → D → D → C → B → A`，三人同理。每次先放村庄，再放连接该村庄的道路。
- 村庄占用唯一共享顶点，邻接顶点不得有村庄；第二座村庄无需连接第一座。道路占用唯一共享边。
- 初始放置免费，命令成功后不可撤销。合法位置查询与命令执行共享判断。
- 玩家资源初始为零，银行每类资源 19 张。第二座村庄放下时，立即按相邻资源地块各领取一张，同类累计、沙漠不发放，并同步扣减银行库存。
- 最后一条道路完成后进入第一位玩家待掷骰阶段。本轮不接受掷骰、普通建造或其他回合命令。
- 非法输入、未知玩家、非当前玩家、阶段错误、无效位置、占用、间距和道路连接错误分别返回可区分的错误码。

规则依据：[CATAN 官方基础版规则，第 12 页](https://www.catan.com/sites/default/files/2021-06/catan_base_rules_2020_200707.pdf)。

## 验收

自动测试覆盖三人和四人完整流程、蛇形折返、非法操作与不变性、起始资源与银行守恒、合法位置查询与执行一致、确定性、schema 校验与 JSON 往返。

2026-10-28：全仓 37 项测试通过，其中新增 16 项核心规则测试；`pnpm format:check`、`pnpm lint`、`pnpm typecheck` 和 `pnpm build` 均通过。本轮不涉及界面接入，未新增界面验收。

本地状态包含全部玩家资源，属于完整核心状态。未来联机时需由服务端执行命令并按玩家投影可见数据，不能直接把完整状态广播给所有客户端。
